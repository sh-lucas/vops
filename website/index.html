vops
Docs GitHub

Your server is
a git repo.

Push compose files over ssh. vops deploys them with podman, serves them over https and snapshots their data on btrfs. One static binary. No cluster, no extra services.

Get started View on GitHub 
$ vops init --domain example.com
$ vops install root@203.0.113.10
$ git add site/compose.yml && git commit -m site
$ vops sync
site
  + web
apply? [y/N] y
# https://site.example.com

Simple on purpose

Everything a small team needs to run apps on its own server, and nothing it doesn't.

GitOps, for real

The repo is the server. Review deploys like code.

btrfs snapshots

Roll back images and data in one command.

Plain linux

systemd, podman and git. Idles at ~30MB of RAM.

Safe releases

Rolling deploys. A failed check keeps the old version up.

Previews with real data

Per-branch copies with a copy-on-write clone of prod data.

Batteries included

https, registry, secrets and a dashboard, built in.

One binary instead of a stack

To deploy one simple app you shouldn't have to deploy ten other things first.

Just vops.

Honest limits: one host, linux and podman only, and snapshots need btrfs. If you need a cluster, vops is not for you. All limitations.
